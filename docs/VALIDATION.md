# 验证记录

## 2.0.3 保存性能修复

保存时最多每块 256 行 / 4 MiB，Photoshop 直接填入 RGBA 缓冲区。RGB 与相邻 Alpha 合并请求；同时有透明度与独立 Alpha 时，RGB 和选中的 Alpha 分两次遍历。删除逐行暂存和手动交错复制。

使用既有 BLP1 JPEG 测试样本（512×512），质量 85、Count 16，模拟宿主调用实际 DLL：

| 指标 | 2.0.2 | 2.0.3 |
| --- | --- | --- |
| RGBA 像素请求 | 2048 | 2 |
| RGB + 透明度 + 独立 Alpha 像素请求 | 2048 | 4 |
| 普通 RGBA 进度回调 | 2059 | 14 |
| 编码 + 全部 mipmap 单次耗时 | 约 16–18 ms | 约 16–18 ms |

这些耗时不包括真实 Photoshop 的调用/UI 开销，不等同于 Photoshop 保存的总耗时。编码结果保持逐字节一致。

新增 `write_transfer` 覆盖 RGB、RGBA、RGB+独立 Alpha、RGB+透明度+独立 Alpha，全部三个 Alpha 选项、16/32 位坐标、奇数尾块、4 MiB 分块、1×1、进度单调性和取消后不写文件。每次输出与直接编码生成的整个 BLP 文件逐字节比较。五组测试全部通过。

## 2.0.2 持久化设置与中文资源

- 在主 `.rc` 入口指定 UTF-8，同时为资源编译器设置 `/c65001`。旧版仅在被包含的 `.rc` 文件内声明编码，导致插件与独立预览的文字不同；参见 [Microsoft RC pragma 文档](https://learn.microsoft.com/en-us/windows/win32/menurc/pragma-directives)。
- 回归测试读取实际 `.8bi` 的 RT_DIALOG 资源，确认“BLP 导出设置”“JPEG 质量”“Alpha 来源”“保存设置”“恢复默认”正确编码为 UTF-16，且移除旧模式与质量预设。
- `persistent_settings` 用进程内隔离的注册表验证默认 85/16、保存/读取、非法值不覆盖、旧 0 迁移为 16、512/1024 尺寸自动限制。测试不改变用户偏好。
- 模拟宿主验证没有动作描述符的正常保存，以及 `plugInDialogDisplay` 模式，都不会弹窗；原有动作参数与像素读写检查继续通过。
- 独立设置窗口完成实际显示检查：中文正常，仅 JPEG 质量、Mipmap Count 和 Alpha 来源，默认 Count 为 16；保存按钮可以持久化设置。
- 编码、宿主、分块读取、设置共四组测试通过。真实 Photoshop 菜单入口及持久化导出行为仍需加载 2.0.2 后在宿主内验收。

## 2.0.1 读取性能修复

既有 BLP1 JPEG 测试样本（512×512，150298 字节）在实际 DLL 的模拟宿主中对比：

| 指标 | 修复前 | 2.0.1 |
| --- | --- | --- |
| 传输块 / ReadContinue 次数 | 512 | 2 |
| 进度回调次数 | 513 | 3 |
| ReadStart（含读取和解码） | 10.76 ms | 10.89 ms |

以上为模拟宿主测试，不是 Photoshop 打开文档的总耗时。解码并非该样本的主要耗时疑点；此补丁移除逐行往返宿主的开销，Photoshop 内的改善仍需重启加载补丁后验证。

新增 `read_transfer` 测试：每个像素字节一致，分块无遗漏、无重叠，跨 256 行边界、宽图 4 MiB 限制、尾块、1×1、16/32 位坐标及传输中取消。原有编码和宿主测试同时通过。测试程序支持 `read_tests.exe <插件路径> <BLP路径>` 对真实文件进行读取验证。
